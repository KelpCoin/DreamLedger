# Factory-Factory

Factory-Factory is the compiler/execution-preparation layer for DreamLedger.

Its job is not to manufacture fake revenue. It repeatedly turns approved offers and evidence-backed opportunities into bounded experiments that can be exposed through authorized acquisition rails.

Loop:

OBSERVE -> COMPILE -> GAUNTLET -> AUTHORITY -> EXPOSE -> TRANSACT -> SETTLE -> FULFILL -> VERIFY -> LEARN -> REPLICATE

Hard boundaries:

- Internal artifacts are not revenue.
- A payment link is not a buyer.
- A checkout is not a settled payment.
- A settled payment is not fulfilled revenue.
- Fulfillment without independent proof is not BusinessTruth.
- External publication, outreach, spending, charging, and production commerce remain authorization-gated.
- Only Truth Oracle verification may promote an event to BusinessTruth.

The factory can prepare many experiments concurrently. It cannot create buyers by assertion.

Current economic factory inputs:

- BEC-PRIME/catalog/offers/approved.json
- BEC-PRIME/compiled/opportunities/ECONOMIC_GAUNTLET.json
- existing Stripe commerce rail
- existing Discord acquisition rail
- DreamLedger evidence/verification infrastructure

The x402/CubeSandbox concept is deliberately represented as an adapter boundary until a real deployed x402 endpoint and a real CubeSandbox runtime exist. No infrastructure capability is claimed merely because a manifest or configuration exists.
