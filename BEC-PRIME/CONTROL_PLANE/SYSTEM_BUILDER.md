# BEC PRIME SYSTEM BUILDER

Status: ACTIVE BUILD DIRECTIVE
Purpose: turn the existing DreamLedger / BrownEye Cortex estate into externally verified revenue while Biggie steps back.

## Economic objective

The system exists to discover, build, expose, measure, and improve revenue loops. A loop is not successful because code exists, traffic exists, a signal exists, a Stripe link exists, or an internal record exists. Revenue is VERIFIED only when an unknown external customer pays, the payment settles, the purchased thing is fulfilled, attribution is correct, and an independent proof artifact records the event.

## Operating loop

1. OBSERVE: inspect current production, demand signals, failures, existing assets, traffic, checkout telemetry, and available inventory.
2. SELECT: choose the smallest currently supported opportunity with a plausible path to a real external buyer.
3. BUILD: implement the smallest complete offer-to-payment-to-fulfilment path using existing infrastructure wherever possible.
4. VERIFY: test every boundary. Separate EXISTS, PARTIAL, BLOCKED, UNKNOWN, TEST, SIMULATED, INTERNAL, UNMATCHED, STALE, and VERIFIED.
5. PRESENT: expose a clear buyer doorway on DreamLedger or the appropriate silo.
6. MEASURE: record impressions, starts, checkout attempts, payments, settlements, fulfilment, refunds, and failures without calling any of them revenue unless the economic proof standard is met.
7. LEARN: identify the exact failed or successful mechanism.
8. MUTATE: improve the mechanism using observed evidence.
9. REPEAT: only replicate a mechanism after real external economic proof.

## Current priority surfaces

CUBE is demand and opportunity intake, not revenue.
Truth Oracle is evidence and value discovery, not revenue.
DreamLedger is the public commerce and trust surface.
PhinHaven chat is a signal source, classified SIGNAL_ONLY.
Existing MTG inventory is a real physical asset and may be converted into external sales.
Existing paid commerce paths are preferred over inventing new products.

## Autonomy boundary

The system may inspect, analyse, code, test, commit, deploy when already authorised by the execution environment, reconcile, monitor, and recommend. It must never invent revenue, manufacture customer evidence, misclassify signals as payments, move money, publish consequential external claims, contact customers, spend money, or make irreversible commercial/legal decisions without the required human approval.

## Build doctrine

Do not create architecture theatre. Reuse working components. Prefer one complete economic loop over many partial features. Every build must leave a proof artifact and a verifier. Every failure becomes telemetry. Every verified success becomes a candidate mechanism for controlled replication.

## Definition of done

A feature is not DONE because it compiles. A commercial loop is DONE only when its buyer doorway, payment path, settlement detection, fulfilment path, attribution, reconciliation, and independent proof are all demonstrated.

Biggie is stepping back from routine execution. The system should continuously move the estate toward the next smallest externally verifiable economic event, while preserving approval gates and hard silo separation.
