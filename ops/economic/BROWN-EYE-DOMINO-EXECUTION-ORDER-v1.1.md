# BrownEye Domino Economic Execution Order v1.1

Status: CANONICAL OPERATING ORDER
Date: 2026-09-20
Principle: The plan is canonical in direction. Reality is canonical in outcome.

## Objective

Operate BrownEye Cortex / CUBE as an economic execution system. Internal architecture is subordinate to verified external economic evidence.

## Execution order

1. Start from an existing buyer-backed opportunity.
2. Identify the reachable buyer or demand source.
3. Define one bounded mission.
4. Produce one concrete deliverable.
5. Perform the smallest authorized external action that can create an observable external effect.
6. Observe the response, payment, acceptance, or other external outcome.
7. Verify the outcome independently.
8. Record the transaction as durable economic truth.
9. Extract the learning.
10. Update the opportunity graph and only then decide the next domino.

## State rule

An instruction to execute is not evidence that execution occurred.

Use explicit states:
PROPOSED -> VALIDATED -> READY -> AUTHORIZED -> DISPATCHED -> EXECUTED -> VERIFIED

Terminal states:
REJECTED, STALE, BLOCKED, FAILED, CANCELLED.

Internal preparation, queued jobs, packets, agent messages, code, dashboards, and database rows do not substitute for an external effect.

## First-domino rule

Do not create a new architecture milestone before testing the first reachable economic transition.

If a reachable buyer-backed action exists, execute that path.
If it does not, do only the minimum work required to make one reachable.
If an action requires an offer, new public release, spending, financial transaction, secrets, or other human authorization, it remains blocked until the required authorization exists.

## Evidence boundary

Signal verification is distinct from payment verification.
Payment verification is distinct from BusinessTruth verification.

BusinessTruth requires:
real external buyer
settled payment where payment is the outcome
correct attribution
fulfillment
independent verification

No self, test, simulated, or fabricated revenue counts.

## CUBE rule

A CUBE is created only after a successful economic cell is independently verified. Clone verified economic behavior, not unproven architecture.

## Anti-theatre gate

Before changing architecture ask:
- What economic transition is blocked?
- What evidence proves it is blocked?
- What is the smallest change that removes the block?

No architecture expansion merely because execution is inconvenient.

## Current operating target

One buyer -> one mission -> one deliverable -> one authorized external effect -> one observable outcome -> one evidence record.

Then repeat.
