Happy Homarid is the creator-membership and community layer. DreamLedger /mtg is the public marketplace, catalogue and evidence-quality layer. Use the Patreon pattern for recurring member value and use MTG as the high-quality public storefront pattern that every cloned silo must pass.

## Monthly housekeeping

At the beginning of each month, refresh the pinned summary using only the work actually delivered. Link the strongest dated examples; explicitly label historical examples; state what is available this month; and retire stale calls. Do not promise a fixed number of alerts unless the creator has deliberately chosen and can keep that cadence.

## Market alert schema

Every alert starts as a draft and contains:
- note_id, silo_id=mtg, observed_at_nzt
- card name, exact set/printing and condition
- source URLs, NZD price observations and source timestamps
- stock status, shipping and other cost fields where observed
- alert type (WATCH / BUY / AVOID) only when evidence justifies it
- action window, reasoning and invalidation conditions
- follow-up date, outcome status and source evidence
- public_release_approved=false by default

No current price, spike, profit or arbitrage claim is published without dated sources. No public post or promotion is auto-published.

## Clone acceptance gates

1. Separate silo identity, content, catalogue, community/member data, analytics and payment boundary.
2. Source-linked public board; empty/held state shown honestly when there is no current evidence.
3. Paid/free difference is understandable without misleading claims.
4. Route parity, access controls, entitlement/fulfilment, read-after-write, silo boundary and clean-clone tests pass.
5. Hosting migration passes preview/runtime, database persistence, route, custom-domain and rollback acceptance before cutover.
6. Revenue is zero until an independent settled payment, correct attribution, fulfilment and delivery evidence reconcile.
