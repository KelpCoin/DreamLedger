# Dream Ledger public contract

DreamLedger gives every registered user one free, persistent public identity page called a Dream Ledger.

## Canonical address

`/u/:handle`

A handle is lowercase and uses letters, numbers and hyphens. The public address is independent of payment status.

## Minimum creation

A user can create a Ledger with:

- handle
- display name
- avatar reference
- short bio
- optional first Dream

Creation uses the existing DreamLedger account. It does not create a second authentication or identity system.

## Public objects

Only explicitly published Ledger items are rendered publicly. The current native item transport is structured and escaped server-side. Links are limited to HTTP(S) destinations.

The first Dream creation surface uses the existing structured Ledger item primitive, presented publicly as a Dream rather than exposing implementation terminology.

## Identity boundaries

- Account owns authentication and private account data.
- Dream Ledger is the public identity container.
- Avatar remains the canonical visual identity reference.
- Truth Oracle evidence may be referenced but is never rewritten by the Ledger.
- Payments are optional commerce layers and are not required to create or view a Ledger.
- External publication tools are adapters, not the canonical identity store.

## Discovery

`/discover` lists active public Ledgers deterministically. Public Ledger URLs are included in the dynamic sitemap generated by the existing Ledger route.

## Safety

The public surface must not expose credentials, private account fields, server environment values, internal orchestration names, filesystem paths, arbitrary JavaScript or arbitrary profile CSS.

## Performance

Public Ledger pages are server-rendered from the existing runtime and public Supabase data path. No per-view generation job is required.

## Acceptance flow

Register -> create Ledger -> choose handle -> add avatar -> add bio -> add first Dream -> publish -> open `/u/:handle` while signed out -> edit while signed in -> observe public update -> discover from `/discover`.

The base flow is free and does not invoke checkout.
