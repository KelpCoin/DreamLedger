# RDTI evidence extraction

This is a technical evidence-extraction surface, not an RDTI eligibility engine.

The packet preserves contemporaneous Git records and exposes the statutory review fields that must be established separately: project identity, core/supporting activity, scientific or technological uncertainty, systematic approach, results, expenditure, entity eligibility, and location.

Unknowns are intentionally emitted as NOT_ESTABLISHED. The compiler must never turn repository metadata into a tax conclusion.

Authoritative review starts with current Inland Revenue RDTI guidance and record-keeping requirements. A generated packet is an evidence input for a qualified reviewer, not a claim or submission.

The first commercial test is a real external software repository supplied or authorised by a prospective buyer. DreamLedger repositories may be used for internal engineering tests only and do not count as an external buyer, sale, or independent evidence.
