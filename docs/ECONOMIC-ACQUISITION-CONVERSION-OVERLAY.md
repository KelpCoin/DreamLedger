## Four hundred acquisition/conversion levers, compressed into operating dimensions

### A. Demand and discovery

Use the existing pain corpus and demand signals to identify:
- active searches
- explicit requests
- quote/RFQ activity
- supplier comparisons
- procurement deadlines
- money-at-risk situations
- manual workarounds
- paid adjacent services
- complaints
- recommendation requests
- decision-maker language
- recurring transaction problems

Prefer observed, current, specific purchasing problems over generic traffic.

### B. Global acquisition

Increase qualified discovery through existing surfaces and infrastructure:
- problem-specific pages
- buyer-specific language
- industry-specific language
- role-specific language
- transaction-specific language
- international terminology
- currency-aware presentation
- structured metadata
- canonical URLs
- sitemap coverage
- internal linking
- machine-readable offer identity
- useful search answers
- high-intent long-tail queries
- existing permitted demand channels

Do not equate page count with acquisition. Every surface must have a distinct buyer/problem rationale.

### C. Visitor-to-buyer conversion

For every live offer, make the following obvious:
- who it serves
- problem solved
- input required
- exact output
- price
- currency
- delivery time
- delivery mechanism
- what happens after payment
- refund policy
- limitations
- next action

Reduce unnecessary decisions. One primary CTA. One clear transaction path.

### D. Price-aware conversion

Price must be evaluated relative to economic value, not in isolation.

Test and observe:
- cost of manual work
- cost of professional alternatives
- money at risk
- value of time saved
- value of decision confidence
- transaction value
- consequence of a bad decision
- buyer urgency
- scope included
- turnaround included

Never use fake discounts, fake anchors, fake scarcity, fake testimonials, or fabricated customer evidence.

The relevant question is:
"Is this price small relative to the problem this buyer is actively trying to solve?"

### E. Trust

Before the first transaction, make uncertainty answerable:
- identity
- contact route
- exact deliverable
- example output
- sample input
- fulfillment mechanics
- turnaround
- refund terms
- information handling
- limitations
- supported countries/payment path where known

Real customer evidence becomes available only after real transactions. Internal tests remain TEST/INTERNAL.

### F. Friction

Remove avoidable barriers:
- mobile usability
- unnecessary fields
- unclear CTAs
- broken links
- unavailable routes
- confusing pricing
- unexplained checkout states
- unclear upload requirements
- unclear delivery
- unnecessary account creation
- repeated information requests

Checkout reliability is a prerequisite, not a marketing optimization.

### G. First-customer acquisition

Prioritize people who already:
- have the problem
- have the relevant documents
- are comparing options
- have a purchasing decision underway
- face a deadline
- have money at risk
- are doing the work manually
- are paying someone else
- are asking how to solve it
- are requesting recommendations
- are comparing suppliers

The system may discover and rank these opportunities. Crossing an external-action authorization boundary still requires the existing human gate.

### H. Fulfillment and post-purchase conversion

The first transaction must produce:
- deterministic intake
- clear scope
- usable output
- durable delivery record
- transaction linkage
- evidence of completion
- independent payment evidence where available

Then measure:
- successful fulfillment
- buyer acceptance
- refund/rework
- repeat need
- referral potential
- adjacent demand
- actual buyer language

### I. Learning loop

Every genuine transaction should update the economic hypothesis.

Observe:
- acquisition source
- exact problem language
- buyer type
- geography where legitimately observed
- price context
- objections
- checkout friction
- fulfillment effort
- delivered value
- payment settlement
- repeat behavior

Do not optimize for clicks, impressions, page count, AI calls, registrations, checkout starts, or internal rows when they are not progressing toward verified economic outcomes.

## Priority order

1. Restore authoritative observability.
2. Verify the actual live offer and payment boundary.
3. Remove concrete purchase-path failures.
4. Identify the smallest qualified external buyer opportunity.
5. Apply the existing human gate if an external action is required.
6. Observe an independently settled payment.
7. Fulfill.
8. Capture independent evidence.
9. Update the acquisition/conversion hypothesis.
10. Only then expand acquisition.
