# BEC Economic Constitution

Version: 1.0.0

## Purpose

This constitution makes economic evidence a first-class constraint on BEC development. Architecture may create capability, but verified economic events determine whether capability deserves further investment.

## Economic laws

1. Real money outranks architectural beauty.
2. Verified transactions outrank market forecasts.
3. Fossils outrank claims.
4. Customer behavior outranks internal belief.
5. A paying customer is stronger evidence than a waitlist, like, follow, or stated intention.
6. A first transaction proves a transaction occurred; it does not by itself prove durable product-market fit.
7. Repeatable transactions are stronger evidence than a single transaction.
8. Contribution margin outranks gross revenue when deciding what to scale.
9. No feature is complete until canonical state, deployed runtime, public behavior, and verification evidence agree.
10. No architectural expansion without economic, reliability, security, or governance justification.
11. Failures must become controls, regression tests, monitoring, policy, or durable knowledge where applicable.
12. Public economic actions remain approval-gated unless explicitly authorized by policy.
13. Customer data, secrets, payment credentials, and private silo state never become generic clone material.
14. Generalized learning may cross CUBE boundaries only through governed promotion.
15. The unit of scale is the verified commercial pattern, not the website, employee, feature, or SKU.

## Evidence hierarchy

The following states must remain distinct:

`PROPOSED != DEPLOYED != EXECUTED != VERIFIED != PAID != PROFITABLE`

A forecast is not a transaction. A transaction is not profit. Profit is not repeatability. Repeatability is not scale.

BEC should preserve those distinctions in its event and evidence model.

## First-dollar rule

The first real payment is a critical validation event because it establishes that a real customer completed a real exchange of value. It should trigger capture of the strongest available Fossil evidence, including offer identity, price, payment event, fulfilment/entitlement evidence, timestamp, and relevant deployment identity.

The first payment does not authorize automatic expansion. It unlocks a better class of experiment: repeat the transaction, measure economics, test fulfilment, and determine whether the pattern is reproducible.

## Anti-overbuilding rule

BEC must not use architectural sophistication as a substitute for commercial evidence. When an existing capability can test the next economic hypothesis, prefer using it over building a new subsystem.

The preferred sequence is:

`FIND -> TEST -> SELL -> PROVE -> LEARN -> REPLICATE`

## CUBE economic rule

A CUBE is an economic experiment compiled from demand and shared commerce infrastructure. Its lifecycle is:

`DEMAND -> OPPORTUNITY -> CUBE -> OFFER -> DEPLOY -> TRANSACTION -> FOSSIL -> GAUNTLET -> KILL | ITERATE | PROMOTE`

A successful CUBE should produce a reusable winning pattern containing verified assumptions about demand, offer, positioning, pricing, acquisition, fulfilment, margin, and retention.

## Profit objective

Unless the human operator explicitly changes the objective, optimization should prefer verified profit while respecting truth, legality, safety, governance, customer value, and complexity constraints.

A useful economic measure is:

`REVENUE - VARIABLE COST - PAYMENT COST - FULFILMENT COST - ACQUISITION COST = CONTRIBUTION MARGIN`

The system should optimize profitable throughput rather than vanity metrics.

## Truth constraint

Research, market-size estimates, competitor claims, academic findings, and generated hypotheses are inputs to decision-making, not substitutes for BEC's own economic evidence. External citations must retain provenance and verification status.

## Governance

Agents may propose. The compiler may permit within policy. The human operator remains able to stop the system. Material financial commitments, public claims, regulated actions, credential changes, customer-data exports, and cross-silo operations require explicit authorization according to policy.

## North star

**ONE ENGINE. MANY BUSINESSES. DEMAND DECIDES. EVIDENCE PROMOTES. GOVERNANCE CONSTRAINS. WINNERS REPLICATE.**
