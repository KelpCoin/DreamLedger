# FIGURE EIGHT SUBSTRATE MAP - 2026-10-02

Purpose: establish the permanent offline, online, and figurehead layers of the DreamLedger substrate so the system can search for monetizable capability continuously while keeping economic truth and authority bounded.

Core principle:

    OFFLINE CAPABILITY <-> ONLINE ECONOMIC RAIL <-> FIGUREHEAD SURFACES
                       \_______________________________/
                              INFINITE LOOP

The figure-eight is not a second architecture. It is a classification of the existing substrate.

## 1. OFFLINE - capability and search

These components can reason, generate candidates, test artifacts, and prepare work without becoming economic truth.

- CUBE: discovery/surface substrate and silo routing.
- Swarm/worker substrate: parallel candidate exploration and task execution.
- Elohim: proposition mutation, offer shaping, candidate refinement.
- Gauntlet: adversarial candidate rejection and preflight.
- Local LM/acceleration: optional computation only; never an economic authority or cloud dependency.
- Repository/runtime proofs: durable implementation and decision evidence.
- Deterministic economic observation modules: read-only projection and state-transition analysis.
- Figure Eight authority layer: authorization boundary for external effects.

OFFLINE RULE:
It may discover, model, test, rank internally, and prepare. It does not manufacture buyers, payments, settlements, fulfillment, or verified outcomes.

## 2. ONLINE - economic and execution rail

These components connect capability to the external world.

- GitHub: versioned source and proof history.
- Render: deployed runtime.
- Supabase: durable operational/economic substrate.
- Stripe: external payment authority.
- Public API routes and machine manifests.
- Toll Road: payment -> entitlement -> scoped key -> wall -> automated result.
- Existing Toll Booths: defined paid digital services.
- Truth Oracle commerce: existing paid entitlement and webhook boundary.
- BridgeRail: signed lease authority and independent Worker B verification.
- Economic reconciliation/proof: external payment and fulfillment evidence.

ONLINE RULE:
External state is observed, not invented. A checkout, API call, internal row, or model assertion is not itself revenue.

## 3. FIGUREHEAD - public identity and customer surface

These components explain and expose the capability without being allowed to become the authority.

- DreamLedger public brand/domain.
- Product names and storefronts.
- toll-road.html / toll-road.json.
- toll-booths.html.
- agent-commerce.json.
- cube.json.
- agent-bridge.html and bridge-tolls.json.
- Individual machine-readable service endpoints.
- Future disposable product surfaces generated from surviving candidates.

FIGUREHEAD RULE:
The figurehead may change daily. The substrate and economic evidence do not.

## 4. PERMANENT VS DISPOSABLE

PERMANENT:
- economic truth vocabulary
- authorization boundaries
- Stripe evidence rules
- fulfillment/evidence rules
- silo boundaries
- provenance
- source control
- proof artifacts
- deterministic verification
- capability substrate

DISPOSABLE:
- candidate offers
- product names
- landing pages
- experiments
- pricing hypotheses
- commercial positioning
- failed public surfaces
- daily swarm hypotheses

A dead offer is allowed to die. Its evidence remains.

## 5. DAILY INFINITY LOOP

1. CUBE observes demand/capability space.
2. Swarm generates candidate economic surfaces.
3. Elohim mutates candidates into concrete offers.
4. Gauntlet attacks the candidates.
5. Surviving candidates are checked for automated fulfillment and proof.
6. Figurehead exposes only eligible surfaces.
7. Online rail accepts authorized external transactions.
8. Stripe/fulfillment/evidence close or reject the economic loop.
9. Observations return to CUBE/Swarm as the next day's search material.

The loop optimizes verified economic outcomes per unit of human attention.

## 6. MONEY GATE

The commercial jackpot is not a model output.

A candidate qualifies for autonomous commercialization only when it can satisfy:

REAL DEMAND
-> REAL BUYER
-> AUTHORIZED ACTION
-> EXTERNAL RESULT
-> SETTLED PAYMENT
-> FULFILLMENT
-> DELIVERY/EVIDENCE
-> VERIFICATION

The system may search indefinitely. It must not claim the jackpot until the external evidence exists.

## 7. CURRENT HIGH-VALUE TOLL-ROAD SURFACES

Observed substrate supports these candidate classes without creating a new economic ledger:

- Automated Gauntlet / candidate preflight.
- Evidence-state / proof validation.
- Quote comparison.
- Document extraction.
- Supplier verification.
- Evidence packets.
- Agent Bridge validation/attestation.

Important: the current new toll-road evidence endpoint is bounded evidence classification, not an independent replacement for the authoritative Truth Oracle.

## 8. CURRENT BLOCKERS

- Dedicated Stripe entitlement prices for the new Gauntlet and Truth Oracle toll-key products are not currently identified.
- Customer toll-key usage accounting is encoded in the signed token but persistent decrement/revocation is not yet a durable metering system.
- CandidateGauntlet's existing internal candidate contract still requires approval/checkout blocking. The commercial Gauntlet surface must remain distinct from any autonomous public publishing authority.
- No live external buyer or settled payment was established by this traversal.

## 9. NON-NEGOTIABLE BOUNDARIES

- No fabricated revenue, buyers, payments, fulfillment, or proof.
- No customer key grants internal worker/lease authority.
- No autonomous spend.
- No public external action without the applicable authorization boundary.
- No second Truth Oracle.
- No second economic ledger.
- No brand preservation requirement for failed offers.
- No human fulfillment requirement for a service advertised as zero-touch.

## 10. FIGURE EIGHT INTERPRETATION

The system has two continuous directions:

CAPABILITY -> MARKET:
discover -> mutate -> attack -> package -> expose

MARKET -> CAPABILITY:
buyer signal -> payment -> fulfillment -> evidence -> learning -> next candidate

The crossing point is Figure Eight authority:
what the machine is allowed to do, for whom, under what authorization, and with what proof.

That crossing point is where autonomy becomes controlled rather than merely unrestricted.
