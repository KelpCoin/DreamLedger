The verification layer

Evidence from request to outcome.

Deterministic checks handle clear contract conditions. Independent evaluators and human review handle ambiguity. Every status should point to evidence.

Keep the decision fields consistent.

Use one row per supplier or offer. Enter known values, keep unknowns blank, and record the source for every number that could change the decision.

Suggested fields: supplier, source URL, quote date, currency, unit price, MOQ, lead time, Incoterms, freight, duties/taxes, packaging, exclusions, validity date, and decision notes.

A stricter definition of done

Proof before settlement.

A transaction is not complete merely because an agent says it is. The record should connect permission, external result, delivered work, and payment state.

Deterministic checks

Use software for objective conditions such as schema validity, required files, hash matches, signature checks, scope limits, and idempotency. A passing check proves only the condition it actually tests.

Judgment and settlement

Request → authorization → delivery → independent evaluation → settlement evidence. Quality disputes, uncertain outputs, and missing proof remain quarantined for review. Missing links stay explicitly unverified.
