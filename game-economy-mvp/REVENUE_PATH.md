# Near-term revenue paths (inside the rules)

Economic truth remains NZ$0 until a REAL_VERIFIED external outcome exists.

## Path A – The game itself becomes the product (preferred first cash)

1. Finish a polished single-player / small multiplayer version of the economic sandbox.
2. Sell access or early access (one-time or subscription) to people who enjoy imperfect-information trading simulations.
3. Cosmetics, scenario packs, and private hosted games are the monetisation surface.
4. In-game currency is never sold for real money and never cashes out.

This path requires no real-world commodity trading and produces clean, repeatable revenue once the product is good enough that strangers pay for it.

## Path B – Human-gated opportunity discovery (higher upside, slower)

1. Player (or operator) uses the game to notice discrepancies.
2. Player creates a REAL_CANDIDATE work packet (`p <n>` in the play loop).
3. Human reviews the packet (HUMAN_REVIEW).
4. Only after explicit approval does any real-world investigation or action occur.
5. If a real buyer/seller/payment happens, BrownEye records the evidence → REAL_VERIFIED.
6. Game may then receive a consequence (reputation, unlock, narrative), but the money is real-world money, not game money.

This path can eventually produce real revenue, but only through the same hard gate that prevents the system from becoming a spam cannon.

## Path C – Verification / pre-screen reports (adjacent)

Use the same “notice discrepancy → gather public evidence → produce a machine-readable report” skill that the game trains, and sell lightweight vendor / market pre-screen reports to procurement or risk teams. This is independent of the game loop and was previously reconnoitred; it still requires finding one real buyer who pays.

## What is explicitly out of scope for now

- Automatic real-world trades triggered by game events
- Selling game currency or cash-out rights
- Any claim that a game profit is real revenue

## Immediate next build steps that serve revenue

1. Make the play loop more interesting (information value, transformation, seasonal pressure).
2. Add a simple web or local UI so a non-technical player can run a session.
3. Ship a free public demo + paid early-access tier (Path A).
4. Keep the Work Packet + approval gate ready for Path B experiments that stay manual and small.

Only REAL_VERIFIED external payments count toward the revenue goal.
