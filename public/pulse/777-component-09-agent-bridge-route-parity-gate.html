Agent Bridge route-parity gate

A route is not sellable because a catalogue says it exists. The manifest, deployed handler, checkout configuration, signed settlement, entitlement, quota, executed work, delivery receipt and reconciliation must describe the same transaction.

Current state: HELD / NOT END-TO-END VERIFIED. This page is an acceptance specification, not a live verifier and not a claim that Agent Bridge checkout is available. Verified external revenue remains NZ$0.00 on the current evidence snapshot.

One route, one evidence chain

  1. Canonical intent: a route ID, SKU, currency, price, call quota, permission scope and fulfilment contract are defined in the approved manifest.
  2. Runtime parity: the deployed handler exists and its route ID, environment configuration and enabled/held state match the manifest.
  3. Checkout attribution: checkout carries stable offer and idempotency identifiers; a created session is not a payment.
  4. Settlement: a signature-verified external event confirms paid status, exact amount, currency and offer. Unpaid, refunded, replayed or mismatched events grant no entitlement.
  5. Entitlement and quota: the settled order grants one idempotent, scoped entitlement with durable quota accounting. Duplicate events return the original receipt.
  6. Bounded execution: the authorized job runs within declared time, token, call, retry, concurrency and spend limits. It cannot silently acquire host access or public-publishing authority.
  7. Delivery: a receipt identifies the requested work, output hash, status, timestamps and evidence references.
  8. Reconciliation: settlement, order, entitlement, usage, fulfilment, refunds and delivery evidence reconcile to the same transaction ID.

Regression suite before opening checkout

  • Missing Stripe or toll-key configuration returns a bounded 503 without creating a Stripe session.
  • Checkout-disabled default stays disabled unless the operator explicitly enables it after acceptance.
  • Unknown route, SKU, currency, amount or manifest version fails closed.
  • Signed success, unsigned event, wrong amount, wrong currency, unpaid session, refund, duplicate event and out-of-order event each have deterministic tests.
  • Quota is durable across restarts; concurrent duplicate redemption cannot over-issue calls.
  • Worker timeout, retry exhaustion, cancellation, dependency failure and delivery failure produce explicit receipts without overstating completion.
  • A complete receipt can be traced back to the same settled order and reconciled without using internal rows as proof of payment.

Current source evidence

  • Toll route implementation currently defaults TOLL_CHECKOUT_ENABLED to false and rejects checkout until the payment-to-delivery acceptance passes.
  • Bounded long-task schema defines task budget, permissions, approval gates and acceptance criteria. Schema validation alone does not prove live worker enforcement.
  • Configuration change adds Render secret references and a disabled-by-default checkout flag; it does not reveal secret values or prove that the live service has them configured.
  • First-dollar acceptance map covers the broader existing payment-to-delivery path.

Promotion rule

Keep free B2B discovery open where it is safe. Keep cheap A2A checkout held until the complete route passes. Expose optional GPU work only through an opt-in isolated worker with tenant separation, hard resource caps, cost metering and a kill switch. Treat DOOH as permissioned inventory until booking authority and proof-of-play are verified.

Truth boundary: a passing test proves the tested contract, not demand or revenue. Verified external revenue remains NZ$0.00 until an independent buyer, attributable settled payment, fulfilled output, delivery evidence and reconciliation agree.
