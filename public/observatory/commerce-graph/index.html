Commerce Graph Adapter

Status: design component, not a live provider integration. This contract is intended to normalize offers from authorized providers so B2B users and A2A agents can compare like with like.

Evidence rules

  • A provider listing, quote, vendor claim, test fixture, click, checkout, purchase, and settled transaction are different evidence classes.
  • Unknown shipping, tax, stock, and returns data stay unknown. Missing data is never treated as free or zero.
  • Currency, variant, quantity and unit must be compatible before offers are ranked by total cost.
  • Source URL, observed time, and a SHA-256 digest preserve provenance.
  • Private supplier documents, buyer details, credentials and licensed raw catalogs do not belong in public observation records.
  • Affiliate eligibility is not a confirmed commission; a commission claim is not settled revenue.

Acceptance gates

  1. Identical inputs produce deterministic rankings and result digests.
  2. Currency conflicts, stale availability, variant mismatch and unknown delivery costs return reason-coded uncertainty.
  3. TEST, SIMULATED and INTERNAL evidence never satisfy an external settlement gate.
  4. Provider adapters are added only after authorized API access, data rights and attribution terms are verified.
  5. Use existing AgentBridge/CUBE and commerce rails; do not create a parallel queue or ledger.
