# BECK Operating Contract

BECK exists to keep the production economic machine observable, verifiable, recoverable, and commercially pointed.

## Non-negotiable truth rules

- Do not call health, traffic, clicks, checkout availability, or intent revenue.
- Revenue requires attributable live payment evidence.
- Delivery and evidence follow payment.
- Failed or stale production checks create an exception, not a success claim.
- Routine observation and evidence collection may run automatically.
- Consequential public posting, spending, or irreversible commercial actions remain approval-gated unless separately authorized.

## Core loop

OBSERVE -> RECORD -> COMPARE -> DETECT -> EXPERIMENT -> SELL -> VERIFY -> LEARN -> REPEAT

## Canonical production nucleus

DreamLedger is the canonical production workload. Other workloads attach to the same control plane and commerce spine rather than creating parallel economic truth systems.

## First economic milestone

RA_000001 is the first verified stranger payment attributable to the canonical DreamLedger Founding Tile offer.

Until that event is proven, the verified revenue figure remains NZ$0.

## BECK heartbeat

The production heartbeat checks health, deployment SHA convergence, the canonical Founding Tile commerce surface, and the live checkout doorway. Evidence is retained as an artifact. Failures are surfaced as a single open GitHub incident to avoid alert spam.
