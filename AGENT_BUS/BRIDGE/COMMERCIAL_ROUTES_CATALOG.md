# DreamLedger Commercial Route Catalog

Status: HYPOTHESIS CATALOG. The 500 combinations below are candidate experiments, not verified demand, approved offers, or revenue. No listing, payment, buyer, traffic, or deployment is evidence of revenue by itself.

## Governing execution rule

Objective: establish one external buyer -> settled payment -> real input -> authorized fulfillment -> delivery evidence -> independent verification loop, then replicate only the proven mechanism. Current truth remains VERIFIED_EXTERNAL_REVENUE = NZ$0.00 until fresh authoritative evidence changes it.

Agents must read `AGENT_BUS/BRIDGE/PROTOCOL.md` and this catalog before proposing commercial work. Use existing offers, checkout rails, CUBE, Elohim, Gauntlet, Agent Bridge, economic observation modules and current data stores first. Do not create a parallel ledger, queue, orchestrator, or truth system.

## No-capital selection filter

Prefer routes that use an existing live surface, cost NZ$0 upfront, need no paid ads, accept customer inputs through an existing secure path, can be fulfilled by existing automation, have clear attribution, and can be stopped quickly. A manual first delivery may prove demand but is not a scalable operating model unless automated or deliberately bounded. Do not spend, create accounts, change payouts, contact people, publish listings, or make other external commitments without the required human/policy authorization. No spam, fake reviews, invented demand, deceptive claims, or unauthorized scraping.

## Evidence and replication gates

- OBSERVED demand signals: relevant search volume, opt-in requests, qualified clicks, input submissions, checkout starts. These are not revenue.
- PAYMENT evidence: provider-side settled/paid transaction, not a created Payment Link, open checkout, test payment, or internal event.
- FULFILLMENT evidence: real customer input was processed and deliverable was created.
- DELIVERY evidence: provider/customer delivery event plus retained artifact or customer confirmation, privacy-safe.
- VERIFIED: independent buyer, settled external payment, fulfillment, delivery evidence, and attribution all agree.
- Replication: require a verified repeat or a second independent buyer before promoting a route to an evergreen cell. Failed routes are recorded as failed hypotheses, not hidden.

## Catalog governance

Each route stays EXPERIMENTAL until a source, customer, unit economics, acquisition method, fulfillment method, compliance constraints, and evidence requirements are recorded. Rank by expected contribution margin, probability of reaching a real buyer, time-to-first-result, zero-upfront feasibility, automation potential and risk. Keep a compact route index in Agent Bridge; retrieve detailed rows only when needed so every agent sees the governing rules without bloating each task.
