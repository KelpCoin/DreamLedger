# Economic Scale Canon v1.0

Scope: all DreamLedger and BrownEye Cortex projects and Agent Bridge workers.

## Mission
Build a compounding global multi-silo ecosystem that discovers real demand, delivers useful outcomes, earns verified external revenue, and replicates proven loops with minimal owner attention and no upfront spend unless authorized. More code, agents, routes, dashboards, and generated pages are not the objective. Current verified external revenue remains NZ$0 until independent buyer, settled payment, fulfillment, and evidence reconcile.

## Authority order
1. Elohim sets strategy, ranks opportunities, and selects bounded objectives.
2. CUBE is downstream: it decomposes objectives into idempotent bounded jobs and routes through existing contracts.
3. Gauntlet checks policy, source quality, privacy, acceptance, resource ceilings, and authority.
4. BECK remains the execution boundary. Do not create a parallel queue, ledger, or orchestrator.
5. Digital Proxy performs external actions only after required policy and authorization checks.
6. Evidence remains independent: CI, artifacts, listings, clicks, checkout starts, internal rows, and test payments are not revenue.

## Figure-eight
Outbound: observe demand → Elohim ranks → CUBE stages jobs → Gauntlet checks → authorized worker executes → artifact returns.
Inbound: validate sources and schema → check privacy and integrity → run tests → attach receipt and limitations → record in existing GitHub, Agent Bridge, Notion, and Airtable surfaces → use the verified component in the next cycle.

Each cycle returns a reusable validated asset or records why it could not. The next cycle must consume it, not merely link it.

## Scale rules
- Explore globally and across lawful domains; do not overfit to one hobby, geography, platform, or offer.
- Generate candidates broadly; promote only with evidence for buyer, distribution, fulfillment, margin, risk, and verification.
- Prefer existing free substrate and existing rails. Paid compute, hosting, ads, and inventory need demonstrated need and authorized budget.
- Cloud work continues independently; local LM Studio/GPU is optional acceleration. Never claim local execution without a local receipt.
- Fan out independent work only, with deduplication, quotas, retry budgets, cost ceilings, stop conditions, and rollback.
- Replicate a cell only after independently verified economics and delivery.
- Keep the owner out of routine routing, auditing, posting, and fulfillment where authorized workers can safely do it. Preserve gates for identity, consent, authority, money, account access, and consequential actions.

## Evidence rules
Each consequential job records task ID, objective, owner, base commit, allowed paths, source/output hashes, acceptance checks, resource ceiling, authority state, timestamps, tests, truth label, limitations, blocker, next owner, and next action.

Truth labels: VERIFIED, UNVERIFIED, CONTRADICTED, STALE, TEST, SIMULATED, INTERNAL, UNMATCHED. Dispatch states: NOT_DISPATCHED, INTERNAL_ROUTED, EXTERNAL_BLOCKED, EXTERNAL_SENT, EXTERNAL_RESULT_OBSERVED, UNKNOWN. Default external effect is NOT_ATTEMPTED; default revenue claim is NONE.

Never put secrets, credentials, private documents, or unnecessary personal data in prompts, Git, Notion, Airtable, logs, or public artifacts. Hashes prove byte identity, not truth or anonymization. Synthetic data remains TEST-only. A passing engineering cycle may still have zero revenue; report both truths separately.

## Owner directive rule
Do not ask the owner to turn on a computer until cloud-side work is complete and a precise local task is ready. The directive must state why, exact action, expected artifact, expected time, and observable success signal.
