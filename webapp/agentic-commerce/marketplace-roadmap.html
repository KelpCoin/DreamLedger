DreamLedger / 777 compounding artifact / 11 October 2026

Make useful work easy to find, buy, and verify.

The marketplace ambition is broad: reusable digital goods, supplier discovery, agent-to-agent services, GPU inference, and eventually digital-out-of-home inventory. The execution plan must be narrow at the transaction boundary: one clear offer, one authorized payment path, one deliverable, and one independent proof of completion.

Operating rule: discovery can be free; scoped execution can be cheap; trust is earned by evidence. A catalogue entry, green workflow, checkout link, or API response is not settled revenue.

Marketplace surfaces

B2B discovery · free

Search before signup

Let people and agents find supplier quote tools, verified templates, stencils, word banks, schemas, workflow packs, connectors, and service providers without paying to browse. Every listing should state who it helps, required inputs, outputs, version, licence, price, constraints, and evidence.

A2A · low-cost calls

Machine-readable service contracts

Each service needs a stable ID, schema, route, price, rate limit, idempotency key, timeout, authentication scope, response schema, error model, and receipt. Start with a read-only manifest and a simulated contract test; enable paid execution only after external settlement and fulfilment are verified.

Reusable digital goods

Sell assets once, improve them continuously

Versioned assets should include a checksum, licence, compatibility range, changelog, examples, automated tests, and a small sample. Revenue options include one-off purchase, team licence, update subscription, and usage-based API access. Do not duplicate assets already present in the repository.

GPU capacity

Rent inference, not the host machine

Offer bounded inference or batch jobs only after measuring available VRAM, throughput, queue time, power/thermal constraints, and uptime. Isolate each tenant, enforce quotas and timeouts, keep secrets out of jobs, limit network access, define retention, and return a signed job receipt. Never expose unrestricted shell or host access to customers.

Programmatic DOOH

Inventory with proof-of-play

Represent each billboard slot with owner authorization, venue, screen specs, date/time inventory, creative dimensions, content policy, audience methodology, price, cancellation terms, and proof-of-play. Begin with a digital inventory schema and mock booking; do not claim physical inventory or buy placements until an actual supply partner and approval process exist.

Trust and settlement

One auditable transaction spine

Track demand signal → buyer → authorized action → external result → settled payment → fulfilment → delivery evidence → verification. Preserve source evidence and idempotency. Unknown is not pass; internal rows and payment intents are not revenue.

Agent Bridge: the release gates

  1. Discover: fetch the live manifest and validate its schema. Record source timestamp and content hash. If the source cannot be fetched, preserve the last snapshot as stale and visibly mark it unverified.
  2. Normalize: accept supported service identifiers and route fields only when their meaning is unambiguous. Reject malformed prices, missing routes, duplicate IDs, unsafe methods, and missing input/output schemas.
  3. Simulate: run contract tests against a local fixture, including malformed input, timeout, duplicate idempotency key, rate-limit response, and error serialization. A passing fixture proves the test harness, not the production route.
  4. Authorize: require an explicit scope and valid entitlement for any billable action. Do not infer consent from manifest access or a previous unrelated purchase.
  5. Settle and fulfil: reconcile provider-side payment state, service execution, output checksum, and delivery receipt. Retry safely without double-charging.
  6. Certify: mark a service production-ready only after a real external payment is settled and a real buyer receives the promised result. Store the evidence IDs and timestamp.

The 777 work programme: small pieces, shared contracts

Wave 0 · close the first-dollar loop

Choose one existing offer. Verify the exact checkout URL, payment webhook, settled-payment reconciliation, entitlement, fulfilment, delivery receipt, refund path, and customer-facing instructions. Acceptance: one independent external buyer completes one paid order and receives the promised deliverable. Scoreboard stays at NZ$0 until then.

Wave 1 · Agent Bridge reliability

Repair manifest normalization, add schema validation and fixture tests, expose freshness/error status, and build a payment-to-entitlement test that cannot confuse a checkout session with settlement. Acceptance: repeatable tests plus one real end-to-end evidence bundle.

Wave 2 · reusable asset catalogue

Define listing, licence, version, checksum, dependency, price, and fulfilment schemas. Index existing assets before creating more. Acceptance: each public listing points to a real downloadable or callable asset, a clear licence, and a tested delivery path.

Wave 3 · free B2B discovery

Build filters, canonical listing URLs, source/freshness labels, and claim/report flows. Monetize verified execution or premium datasets, not basic search. Acceptance: useful listings are crawlable, differentiated, source-grounded, and connected to a clear commercial next step.

Wave 4 · cheap A2A commerce

Publish machine-readable contracts, rate cards, usage caps, idempotency, signed receipts, and scoped keys. Acceptance: a test agent can discover a service, estimate cost, authorize a call, receive an output, and reconcile a receipt without exposing secrets.

Wave 5 · GPU inference exchange

Measure actual capacity, package one safe inference endpoint, add queueing, quotas, abuse controls, tenant isolation, and metering. Acceptance: repeatable benchmark, bounded job, cost model, and a real paid job receipt before increasing capacity.

Wave 6 · DOOH inventory exchange

Model placements and booking rules first; recruit supply only through authorized integrations. Add creative review, payment/escrow state, proof-of-play, and dispute evidence. Acceptance: one authorized inventory source and one verified campaign, not a fabricated billboard catalogue.

Wave 7 · marketplace federation

Standardize seller identity, product/service schemas, policy enforcement, reviews tied to verified transactions, disputes, returns, and exportable seller data. Acceptance: portable listings and reliable order state across independent sellers. Compete on trust and low friction, not on claiming to replace incumbents before usage proves it.

Compounding rules

  • One expedition should leave a durable artifact: a tested component, source-grounded page, schema, fixture, run receipt, or documented blocker with its next action.
  • Never publish filler merely to increase page count. Every public page must answer a distinct query with attributable facts, a useful tool or workflow, clear limitations, and links to relevant existing pages.
  • Do not fabricate demand, inventory, regulatory conclusions, benchmarks, buyer activity, settlement, or production readiness.
  • Keep commercial routes separate from informational pages. Do not cannibalize existing product URLs.
  • Prefer one end-to-end paid fulfilment proof over hundreds of unverified candidate services.
  • Every generated artifact records source URLs, observation time, code version, test results, freshness, and explicit unknowns.
